# 任务调度Skill（元能力层）

接收输入文件，按**教材章节目录串行调度**，在阶段间传递数据，控制全流程与版本产出。

## 调度顺序

```
读入配置 → 语料装配（章节/题目/解析/考点/公式/种子对齐）
   └→ 阶段一 冷启动：种子模板导入Skill（幂等，已导入的文件跳过）
        └→ 阶段二 增量迭代：for 章节 in 用户选定顺序
              ① 单题标准化拆解Skill     逐题 5 字段（批量推理、逐题记录）
              ② 本质匹配与模板迭代Skill  逐题三档判定并即时写库（章内快照冻结）
              ③ 章节分类与组织Skill      章内合并去重
              ④ 扩展点：所有生成型 Skill（hook=post-chapter）
              ⑤ 质量校验层 3 个 Skill     等价 / 覆盖 / 边界
              ⑥ 产物渲染：模板库 vX.Y.md + 单题拆解.md + 校验报告.md
           每 crossMergeEveryChapters 章 → 跨章共性合并
           阶段三 全局收敛 → 万能通法手册.md + 附录考点-通法对应表
```

## 关键设计约束

1. **章节优先**：不做跨章节批量聚类，严格按目录顺序推进，符合知识依赖关系。
2. **可重放（deterministic replay）**：拆解阶段与模板库状态无关；匹配阶段在章内使用**冻结的库快照**作为提示词上下文。因此同一批答案可反复重放，不会因迭代顺序产生漂移。
3. **阶段闸门**：任一阶段存在「待作答」任务时，暂缓后续阶段（拆解未完 → 不进入匹配；匹配未完 → 不进入合并与质检），避免模板库状态漂移导致缓存失效。回填后重跑自动续接。
4. **幂等**：种子按文件名记账去重；拆解/匹配按 problem_id 去重，重跑只补未完成的题。
5. **事件流**：每个阶段都向 `data/runs/<id>.jsonl` 落事件并通过 SSE 推送前端（`pending`/`merge`/`qa`/`chapter-end` 等类型）。

## 收敛控制

| 时机 | 动作 | 目标 |
| --- | --- | --- |
| 每章结束 | 章内合并去重 | 消除同本质多模板 |
| 每 N 章（默认 5） | 跨章共性合并 | 本质相同的跨章节模板合并且不同场景降为分支 |
| 全局终稿 | 迭代合并 + 强制降级兜底 | 一级通法严格落在 15~20 个区间 |
